Check a memo

How it works

LIST

Muse lists each claim in the memo. It copies the words exactly and does not fix anything.

POINT

Muse points to where the filing reports the metric. It is not told the memo's number, so it cannot lean toward it.

READ

Plain code reads the PDF's own text at that spot and gives the verdict. Muse never decides.

RELEASE

Only a memo where every number matches can be sent on. A person must approve it first.

Muse writes, code checks

Ask for a draft

Muse writes a short memo from the filing. Code then checks it like any other. Muse does not mark its own work.

A person releases

Approvals

Nothing is released until a person says yes. Each yes is tied to the exact content it saw.

Only the operator can approve or reject. The token stays in this page's memory. It is gone when you reload.

Hash-chained ledger

Record

Every step goes on a ledger. Each line holds the hash of the line before, so a changed line breaks the chain.

Plugins and capabilities

Rules

Each row is one capability, declared by a plugin in code. It states if it reads or acts, if a person must approve, and how code checks the result. The page and the command line use the same door.

The program will not start if an action has no person approval, or if a capability does not say how it is checked.

Measured on known answers

Score

What the checker did on numbers we already knew the answer to.
